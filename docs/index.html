Part V

1: If I wanted to publish a map of West Town requests, residents may feel their privacy violated in that they did not consent to their requests being made public. Anyone could easily see the map and learn things about specific residents who live there. For example, an insurance company could use the map to influence the insurance rates for residents who live there. Therefore, a map containing specific addresses of the requests would need to be de-identifiable and have noise added to it. I would do this by utilizing perturbation and removing identifiers. I would remove the street_address columns and add 5% noise to obscure the data. This will help ensure use of summary statistics instead of individual records and exact value be hidden.
2:A city manager can be misled by assigning repair crews to request counts because people can call in multiple requests for the same issue. One way to check is by aggregating the data. This could be done by utilizing the street_address column to group requests that have the same street_address, report date and service request so that if multiple people report the same problem to the same location, only one crew is called in to fix it. This allows the city manager to group projects and provide better accuracy for repair crews.
3:The web scraping done in Part II was appropriate because the data was public and non-personable as the data for communities was about general areas. Furthermore the data regarding the books was purely factual except for the star ratings which was generalized from multiple reviews. Situations where one should not scrape without further review is when the data is not public or behind a pay-wall and there is identifiable information included. A civic data example situation would be web scraping voter information to see how many individuals living in a neighborhood are registered to vote. Even if the information is meant to help empower voters, it is an ethical and legal violation despite a well-intended goal.
